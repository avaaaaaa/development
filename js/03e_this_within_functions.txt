* "this" keyword within function(){} is not the same "this" outside
	it binds a new value to "this"
"this" keyword within the arrow functions is the same "this" outside
	it does not bind a new value to "this"


* when using "this" keyword within functions and arrow functions,
	make sure to log "this" first and see its value to prevent unexpected results
let's take a look at the following example


class App {
    constructor() {
        this.navbar = document.querySelector("#navbar");
        console.log(this, "'this' within constructor");
        this.initEvents();
    }

    initEvents() {
    	this.navbar.addEventListener("click", function() {
        	console.log(this, "'this' within function");
        	this.navbar.remove();
        });
    }
}

const app = new App();


Object { navbar: div#navbar } 'this' within the constructor
	"this" becomes the Object{}
<div id="navbar"> 'this' within function
	"this" becomes the #navbar
	

Every time you create a function() {}, js will define a new value of "this" inside of that function.
	and the value of "this" is actually the object, the element etc. that is calling "this"
so, basically "this" within the listener function is not the same as "this" outside the function
and "this" within the listener function does not have the "navbar" property
	thus this.navbar.remove() will throw an error when clicking on #navbar


possible solutions to the problem above:

** capture "this" outside the function (not recommended)
initEvents() {
    const capture = this;
    this.navbar.addEventListener("click", function() {
        capture.navbar.remove();
    });
}


** binding the value of "this"
initEvents() {
    this.navbar.addEventListener("click", function() {
        this.navbar.remove();
    }.bind(this));
}
// with "bind(this)", we pass the outer value of "this" into the inner function


** arrow functions (recommended)
initEvents() {
	this.navbar.addEventListener("click", () => {
        this.navbar.remove();
    });
}

arrow functions do not create a new value of "this".
Instead, they give you the same value as the one outside.

Arrow functions are said to have a Lexical scope
it means that "this" within them is the same as the outer function.


* check out the output

class SayHello{
	constructor(){
		this.userName = "sam";
		console.log(this);	// SayHello { userName: "sam" }, "this" became the object
		setTimeout(function(){
			console.log(this);	// Timeout{...}, "this" became the function that is calling "this" 
			console.log(this.userName);	// undefined, because the function does not have the userName property
		}, 100);
	}
}
new SayHello();


* check out the output

const person = {
	name: "my name",
	printName: function() {
		console.log(this);
		console.log(this.name);
	}
}

console.log(this);	// undefined
person.printName();	// function(){} binds "this" to the "person" object
// so, "this" is the "person" object
// this.name is "my name"

console.log("\n\n\n");

const myFunc = person.printName;
myFunc();
// "this" refers to "person" object when calling person.printName()
// but "this" does not refer to anything when calling myFunc()
// thus, accessing "name" through "undefined" causes TypeError


* check out the output

const person = {
	name: "my name",
	printName: () => {
		console.log(this);
		console.log(this.name);
	}
}
console.log(this);	// undefined
person.printName();	// arrow functions do not bind "this", thus "this" is still "undefined"
// so, "this" is "undefined"
// this.name is equal to undefined.name which causes TypeError

console.log("\n\n\n");

const myFunc = person.printName;
myFunc();
// the behaviour of myFunc here is the same as in the previous example
