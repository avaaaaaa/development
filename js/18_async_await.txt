* with async-await, we are actually doing the same thing as promises
it is used to make the promises easier to read and write
	but we are still working with promises in the background
remember that there's nothing wrong with promises and you can keep on using promises if you prefer them. 
At the end of the day, async/await is hiding your promises behind the async and the await keywords.


* an example of code transition

const getUsers = () => {
    fetch("https://jsonplaceholder.typicode.com/users")
        .then(response => response.json())
        .then(data => {
            console.log(data);
        });
}

// with async-await:

const getUsers = async () => {
    const response = await fetch("https://jsonplaceholder.typicode.com/users");
    const data = await response.json();
    console.log(data);
}

// Sample usage
getUsers();


* async
this keyword implies that the function is doing some asynchronous work
it wraps the return value of the function with a promise
definition
	const func = async function(){}
	const func = async () => {}


const getNumber = async () => {
	return 42;
}

// Sample usage
getNumber().then(value => {
    console.log(value); // 42
});


** class methods can also be async
class User {
    async isAdmin(type) {
        return type === "admin";
    }
}

// Sample usage
const user = new User;
user.isAdmin("admin").then(value => {
    console.log(value); // true
});


* await
'await' expressions are only allowed within async functions and at the top levels of modules
it pauses the execution of the current function, until the promise resolves (or rejects).
And, then, it will automatically resolve it (call .then() on it), and return the result
You can only await a promise (or an object that has the .then())


getNumber().then(value => {
    console.log(value); // 42
});

// becomes:

const init = async () => {
	const value = await getNumber();
	console.log(value);
}
init();


* logging items of an array between the same time intervals
notice the difference of initial "count" value and where "count" is increased between two approaches

** without async-await

const wait = milliseconds => {
	return new Promise(resolve =>{
		setTimeout(resolve, milliseconds);
	});
}

const interval = 1000;
const items = [1, 2, 3, 4, 5];
let count = 0;

items.forEach(item => {
	wait(interval * count).then(()=>{
		console.log(item);
	});
	count++;
});
console.log("iteration ends, printing starts");


** with async-await

const wait = (timeout) => {
	return new Promise(resolve => {
		setTimeout(resolve, timeout);
	});
}

const items = [1, 2, 3, 4, 5];
const interval = 1000;
let count = -1;

items.forEach(async item => {
	count++;
	await wait(interval * count);
	console.log(item);
});

console.log("iteration ends, printing starts");


* check out the outputs
remember that "await" pauses the execution until the promise resolves or rejects


const wait = milliseconds => {
	return new Promise(resolve => {
		setTimeout(resolve, milliseconds);
	});
}

const init = () => {
	wait(1000).then(()=>{
		console.log("1 second passed");
	});
	console.log("step 2");
}

init();
// output:
// step 2
// 1 second passed


const init = async () => {
	await wait(1000);
	console.log("1 second passed");
	console.log("step 2");
}

init();
// output:
// 1 second passed
// step 2


const init = async () => {
	console.log("lets begin");
	await wait(1000);
	console.log("1 second passed");
}

init();
console.log("step 2");
// output:
// lets begin
// step 2
// 1 second passed
