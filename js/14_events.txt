* we can react & respond to user actions with .addEventListener(event, callback) method
event is the user action we want to respond
callback is the respond to the event


* button click

<button id="app-button" style="height: 100px; width: 100px;">Click Me</button>
<script>
    let counter = 0;
    const button = document.querySelector("#app-button");
    button.addEventListener("click", ()=>{
        counter ++;
        button.textContent = `You clicked ${counter} time(s)`;
    })
</script>

** accessibility note for click events
It's important to note that in order to make your website accessible for users with screen readers, you should only add a click event listener on <button> and <a> elements.

While it is possible to add it on other items, you may end up making those elements not accessible for screen reader users if you don't add the necessary attributes (role & tabindex).

An easier solution would be to wrap any item with a <button> element and then adjust the styles of that button to not make it look like a button. For example, if you want to make an img element clickable, you can wrap it with a <button> and style it with all: unset which removes all the styles of the <button>:

// html
<button class="clickable">
    <img src="..." alt="...">
</button>

// css
.clickable {
    all: unset;
    outline: revert; /* keep the outline so that it's focusable */
}
With the code above, you can have the click event listener on the <img> without breaking accessibility!

.addEventListener("click", event => {

* event.currentTarget
it refers to the element to which the event listener has been attached
When we refactor the event listener callback into a named function, it becomes absolutely necessary to use event.currentTarget because the button variable will not be available within that function
the reason why we refactored the callback function into a named function is
	to improve readability and flexibility
	with named functions it is easier to notice & change & reuse the functionality of event listeners 


const buttons = document.querySelectorAll("button");

const handleButtonClick = event => {
    console.log(event.currentTarget); // event.currentTarget is the 'button' that was clicked.
    // console.log(button) won't work, because button is not defined here
}

buttons.forEach(button => {
    button.addEventListener("click", handleButtonClick);
});


** a note on "currentTarget"
when inspecting this property on browsers' dev tool console, its value will be null
currentTarget is only available when the event is triggered (example: when the button is clicked)
but you won't be able to read its value later on in the dev tool console.
You can either log event.currentTarget directly (rather than event) or, you can add a debugger; statement which will pause the execution of your code and thus allowing you to see the event.currentTarget in the dev tools console:

button.addEventListener("click", event => {
    console.log(event);
    debugger; // pause execution so that we can see event.currentTarget in the dev tools
});

* event.target
this will return the element that was clicked
	but not necessarily the element to which the event listener has been attached.


<button>
    Hello <strong>world</strong>
</button>

const button = document.querySelector("button");

button.addEventListener("click", event => {
    console.log(event.target); // not recommended
});

depending on where the user clicks inside the button.
	The event.target here might return either the <button> element or the <strong> element
you will rarely ever need it.
	There is, however, one use case for event.target and that is "event delegation"
	this can also be useful in some scenarios when building User Interface libraries
This is why you should stick to event.currentTarget.
	here, it'll always return the <button> no matter where the user has clicked inside that button.
